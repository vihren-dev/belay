# JSONB (ADR 0015, slice 4)

Created 2026-10-20. Status: open.
Status file: [status](20261020-jsonb.status.md).
Specification: [ADR 0015](../docs/adr-0015-functions.md), D6.

## Process

As for slices 1 to 3: local jj commits with the tests that touch each one; at the end of the
slice the local verdict, the corpus, and `just test-full`.

## Outcome

1. **JSONB arguments.** Each JSON function reads a BLOB argument as SQLite 3.51.0 does
   (checked natively):
   - a BLOB that passes SQLite's quick check (`jsonArgIsJsonb`: a known node type, a header
     whose payload size fills the BLOB, and for a short BLOB that starts like JSON text the
     full validity check `jsonbValidityCheck`) is JSONB;
   - any other BLOB is read as JSON text (tag-20240123-a in SQLite), except as a value of
     `json_array`, `json_object`, `json_quote`, the edit functions and the JSON aggregates,
     where it fails with `JSON cannot hold BLOB values`;
   - `json_valid(blob, flags)` gives SQLite's answer for each flag.
   The model reads JSONB as the node tree when the BLOB is valid and canonical: it passes the
   full validity check and is the encoding that SQLite's encoder gives for that tree. Other
   JSONB is a `may` fault (out of scope): SQLite does not check it fully, and its edits keep
   the headers as they are.
2. **JSONB results.** `jsonb`, `jsonb_extract`, `jsonb_array`, `jsonb_object`, `jsonb_set`,
   `jsonb_insert`, `jsonb_replace`, `jsonb_remove`, `jsonb_patch`, `jsonb_group_array` and
   `jsonb_group_object` give the BLOB that SQLite gives, byte for byte:
   - each header is the smallest that holds its payload size (`jsonBlobAppendNode`,
     `jsonBlobChangePayloadSize`);
   - `jsonb_array`, `jsonb_object`, the JSONB aggregates and `jsonb_extract` with several
     paths write JSON text and convert it, so a string is `TEXT` or `TEXTJ`;
   - the edit functions insert SQL text as `TEXTRAW`, as `jsonFunctionArgToBlob` does;
   - `jsonb` of a JSONB BLOB gives the BLOB unchanged;
   - `jsonb_extract` with one path gives the JSONB of a selected array or object and the SQL
     value of a selected scalar.
   A JSONB result has no JSON subtype, and `->` still gives text.
3. **Faults.** `JSON cannot hold BLOB values` is a `must` failure in a query without `FROM`;
   JSONB that the model does not read stays a `may` fault.

## Tests

- Lean examples of the encoder (each header size, each node type), of the quick and the full
  check, of the canonical check, and of each `jsonb_*` function.
- An authored corpus (`conformance/authored_jsonb.py`), each case with a kernel proof,
  recorded as a new corpus: the encodings of each node type and header size, each `jsonb_*`
  function, JSONB as an argument of the text functions, a BLOB read as text, the BLOB value
  error, `json_valid` flags on BLOBs, and JSONB in table cells.
- The verdict of every corpus: cases that newly agree and none that leave AGREE.
- Mutants: a header that is always one byte longer than needed, `jsonb_set` that stores SQL
  text as `TEXT`, and a BLOB that is never read as text; each killed by an authored case.

## Key points

- **Files.** `Json/JsonbOffset.lean` has the header sizes that `json_each` already uses;
  `Json/Extract.lean` (`parseJsonArgument`), `Json/Valid.lean`, `Json/Build.lean`
  (`sqlValueText`, `sqlValueNode`), `Json/JsonApply.lean`, `Resolution/JsonFunction.lean`,
  `Resolution/Calls.lean`, and the aggregates in `QueryEval.lean` and `Resolution/ExprForms.lean`.
- **The tree has the JSONB node types.** `JsonNode` keeps each node type and payload, so the
  encoder writes each node with its type code and payload; containers hold the encodings of
  their children.
- **Kernel reduction.** The decoder and the validity check are structural over fuel, as the
  other byte readers are.
- **Shell probes.** The 3.51.0 shell turns `\uXXXX` in its input into the character; write a
  backslash in a probe as `char(92)`.
