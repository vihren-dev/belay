## Progress

- 2026-10-21: the task file, after a scratch probe of the parser library in `lake lean`.

- 2026-10-21: outcomes 1 and 2 and the binding of outcome 3. The package `belay`
  (`packages/belay`, `lakefile.lean` with precompiled modules and the C shim
  `c/parser_shim.c` as an `extern_lib`; the parser library's folder from
  `BELAY_PARSER_LIBRARY`), its derivation `surfacePackage` and the suite `surface`
  (`tests/surface_parser_test.py`, `tests/surface_layers_test.py`). `#sql_parse` shows the
  commands of valid SQL and SQLite's grammar error at its column. Found: Lake compiles C with
  hidden symbols, so the shim exports its functions itself; `lean` without the package's plugin
  aborts at the first parser call (an uncaught exception), and with the parser library missing
  it stops with the loader's error. Checks: the suite passes in Nix (7 tests); `just
  test-source` passes after the fixtures got their category.

- 2026-10-21: the review's fixes: `#sql_parse` counts commands under `EXPLAIN` too, the grammar
  errors say what the user can do, the layer test names its allowed Nix lines, and the shim and
  the fixtures are documented.

- 2026-10-21: the measurements of prototype 1 on Linux (`experiments/surface-s1/`): the texts of
  the frozen corpora (`texts.py`, 14,430 texts), the parse time in Lean and in Python
  (`ParseTime.lean`, `parse_time.py`), and the editor's diagnostics with and without the parser
  library (`editor.py`). The report (`README.md`) has the results.

- 2026-10-21: candidate A of outcome 4, the Lean port of the translation
  (`packages/belay/Belay/Sqlite/Translation/`). Its result equals the Python translation's for
  all 14,430 texts of the frozen corpora, and each statement decodes to `Syntax.Statement`
  (`experiments/surface-s1/TranslateA.lean`). The test `tests/surface_translation_test.py`
  compares both over the authored corpora. Found: the surface's Lake library with the root
  `Belay` took the model's modules as its own, so the library now names its modules.

- 2026-10-21: candidate B of outcome 4, the translation in C (`experiments/surface-s1/candidate-b/`),
  a library beside the parser library that reads its parse document. Its result equals the
  Python translation's for all 14,430 texts (`translate_b.py`), and the surface suite builds it
  (`candidateB` in `build-support/tests.nix`) and compares it over the authored corpora. The
  report has both candidates and a summary for the choice.

- 2026-10-21: the end checks on Linux. `just runtime-package` passes. `just test-nix` found
  that two tests that evaluate the Nix files with a private source tree lacked the surface
  package and candidate B; they now include them. The predictions of the frozen corpora at the
  top of S1 are the same Nix output as after the move.

- 2026-10-21: the owner chose candidate A. As the task file says, the port now builds the
  model's syntax: each node is the `Syntax.Statement`, `Syntax.Expr` or other value with a range
  tree (`Span`) in the shape of the model's path steps, without JSON between the parse tree and
  the model. The comparison decodes the Python statements with the model's codec; all 14,430
  texts are equal. The fixture `tests/surface/TranslationEquality.lean` is now also the
  measurement, in place of `experiments/surface-s1/TranslateA.lean`. Found: the precompiled port
  calls the model's compiled code, so the surface's Nix build keeps the model's shared library
  (`sharedRequires`), and the tests give `lean` Lake's module setup (`--setup`) instead of
  `LEAN_PATH`, which cannot find the model's modules beside the surface's.
