# S1: SQL text in Lean, measured before it is built (ADR 0017, D2)

Created 2026-10-21. Status: OPEN.
Status file: [status](20261021-surface-s1.status.md).
Specification: [ADR 0017](../docs/adr-0017-user-surface.md), D1 (S1), D2 and D6;
[ADR 0016](../docs/adr-0016-model-and-surface.md), D1 and D2 (the surface package and its layer
rules); the target user guide, "Writing SQL in Lean files" and open questions 8 and 9.
Depends on: [the model's move](20261021-model-move.task.md) (ADR 0016, D3).

## Scope

S1 starts with two prototypes and their measurements (ADR 0017, D2). The owner then chooses
the candidate of the translation. This task ends with the measurements, and stops for that
choice: the replacement of the Python translation and the elaborators that use the chosen
candidate are the next task, after the choice.

## Outcome

1. **The surface package** (ADR 0016, D1). A Lake package `belay` in `packages/belay`, with its
   own Nix derivation and its own suite in `tests/nix_suites.json`. Its root module `Belay`
   imports `Belay.Sqlite` and defines nothing; all its code is under `Belay.Sqlite`. It imports
   only `Init`, `Std`, `Lean` and the model's roots `Belay.Sqlite.Model` and
   `Belay.Sqlite.Model.Codec`.
2. **The layer rules are a test** (ADR 0016, D2), in the surface's suite: no Lean file of the
   model, the verifier packages or the conformance runner imports a surface module; every
   surface import of the model is one of its two roots; and the packages that the installed
   runtime, the kernel gate and the conformance runtime are built from (`build-support/`) do not
   contain the surface package.
3. **Prototype 1: the parser in the Lean process** (guide question 8). A Lean binding of the
   parser library's C API (`parser/library.h`: the metadata and a parse) that a file calls
   while it elaborates, in `lake build`, in `lake env lean`-style runs that Lake sets up, and in
   the editor's Lean server. A command of the prototype parses SQL text at elaboration and
   reports SQLite's grammar error at the error's position in the text. The measurements:
   - that it loads on Linux, and on macOS, in the pinned Lean release (4.34.1);
   - the time to parse the SQL texts of the frozen corpora from Lean, in total and per text,
     beside the Python binding's time for the same texts;
   - what the editor shows when the library is missing: the diagnostic and where it appears.
4. **Prototype 2: the translation in the elaborator** (guide question 9). Two candidates, each
   from SQL text to the model's statement syntax (`Syntax.Statement`, with the source range of
   each node as `belay/sqlite/located.py` keeps it), with the same refusals:
   - **A**, a Lean port of the Python translation (`belay/sqlite/syntax*.py`, `sql_tree.py`),
     from the parser's parse document;
   - **B**, the translation in the C parser library, which gives the model's syntax as the JSON
     that the codec reads (`Belay.Sqlite.Model.Codec`), with the ranges.

   The measurements, for each candidate, over the SQL texts of the frozen corpora: the share of
   texts whose result equals the Python translation's (the statements and their ranges, or the
   same refusal with its status, range and message); the acceptance bar is all of them. And the
   size of the code that would exist twice if the candidate is chosen: the lines that repeat
   knowledge that another component also holds (for A, the Python translation until it is
   replaced; for B, the JSON shape that the Lean codec also decodes).
5. **The report.** `experiments/surface-s1/README.md` gives each measurement with its method,
   the machine, the date and the commit, so that the owner can choose the candidate.

## Tests

- The surface's suite: the layer test of outcome 2; the binding's metadata and parse calls; a
  Lean file that elaborates a prototype command over valid SQL, and one whose SQL has a grammar
  error, with the diagnostic at the error's position; and the loader's message when the
  library is missing.
- The equality measurement of outcome 4 as a test of each candidate over the authored corpora's
  texts (fast), with the full frozen corpora in the report's measurement.
- `just test-full`, `just test-nix`, `just test-scheduled` and `just runtime-package` pass, and
  the predictions of every frozen corpus do not change.

## Key points

- **Precompiled modules.** The Lean interpreter calls an `@[extern]` function only through
  native code: the module that declares it must be compiled to a shared library that Lake loads
  (`precompileModules`, and the C shim as an `extern_lib`, which needs a `lakefile.lean`). A
  scratch probe (2026-10-21) loaded the library into `lake lean` on Linux, and Lake's
  `setup-file` gives the editor the same shared libraries; `lake env lean` alone does not load
  them. With the library missing, the probe's file showed `error loading library ... cannot open
  shared object file` at its first line.
- **The library's path.** The parser library is a Nix build (`build-support/parser-library.nix`);
  the surface links it by an absolute path (rpath), as the Python binding loads it by an
  absolute path and never searches the environment. The Nix derivation of the surface and a
  developer's build each need that path.
- **macOS.** The development machine is Linux. CI's check job runs on macOS (`macos-14`) for
  manual runs and on `main`; the macOS measurement uses such a run of the surface suite.
- **The model's syntax in Lean.** Candidate A builds `Syntax.Statement` values, and candidate B
  JSON for `Codec/Resolution.lean`; the comparison with the Python translation decodes both to
  one form. Equality of syntax needs the ranges too, because model restrictions are reported at
  a statement index and a node path (`located.py`).
- **Measured, not built.** The candidates are prototypes for a choice: they reach the acceptance
  bar or report the share that they reach, and each has the tests that its measurement needs.
  The candidate that the owner does not choose is deleted with the Python translation in the
  next task. The surface package, its layer test and the binding stay.
- **Outside the trusted base** (ADR 0017, D6; ADR 0016, D2): the gate, the judge's subject and
  the installed runtime do not build or load the surface.
