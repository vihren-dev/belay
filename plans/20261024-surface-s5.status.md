## Replay unit

- `SqlSource` retains source text/ranges in definitionally irrelevant metadata.
  SqlTerm annotates the bound script body; DbBang annotates its resulting database.
  Recovery works through named definitions, application and explicit rebinding.
  Metadata never replaces validation of the actual script or database.
- `ReplayEvaluation` audits input types/dependencies and kernel-checks equality
  between the original projection and its reified compiled result. A divergent
  compiled implementation cannot attach different data to a certificate.
- `ReplayConstruction` validates exact catalogs, rowids and cells using the
  existing model runner. Original construction text supports constrained schemas;
  the fallback handles ordinary tables with generated sequential rowids.
  Unsupported reconstruction remains unavailable, rather than changing the witness.
- `ReplayScript` retains original SQL and bindings, obtains model observations
  through the existing step API and emits SQLite shell input. Model restrictions
  remain unavailable observations, not native errors. Plain Lean predicates get
  database reconstruction without an invented query.
- This shell path refuses clock/counter reads. It creates the shell binding table
  only for bound scripts, and conservatively refuses validated text/construction
  that mentions sqlite_parameters. This includes supported DROP IF EXISTS, which
  could otherwise remove the helper before a later bound statement. The public
  certification primitives and explicit construction/text inputs remain available.
- Value spellings preserve text/BLOB bytes and storage class, including NULs and
  quotes. Invalid integers, NaNs and REAL spellings that lose their bits are refused.
  Witness.environment documentation now distinguishes the Env type from domain
  premises such as completeness, which refutation checks when required.
- The focused Nix surface gate passes 14 checks (60 deselected) at
  `/nix/store/qh5lxq6ycrswh0bfzaym8cjc3yc16fk4-sqlite-verifier-test-replay-1`.
