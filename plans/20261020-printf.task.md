# printf and format (ADR 0015, slice 6)

Created 2026-10-20. Status: DONE.
Status file: [status](20261020-printf.status.md).
Specification: [ADR 0015](../docs/adr-0015-functions.md), D8.

## Process

As for slices 1 to 5: local jj commits with the tests that touch each one; at the end of the
slice the local verdict, the corpus, and `just test-full`; then the end of the ADR.

## Outcome

1. **`printf(format, ...)` and `format(format, ...)`** give the text of SQLite 3.51.0's
   `sqlite3_str_vappendf` with `SQLITE_PRINTF_SQLFUNC` (checked natively):
   - the conversions `d`, `i`, `u`, `r`, `x`, `X`, `o`, `p`, `f`, `e`, `E`, `g`, `G`, `s`, `z`, `c`,
     `q`, `Q`, `w`, `%` and `n`; `T`, `S` and an unknown conversion end the output;
   - the flags `-`, `+`, space, `#`, `!`, `0` and `,`, the width and the precision, also `*`,
     which reads an argument as a C `int`; `l` and `ll` are ignored;
   - a field reads the next argument as `sqlite3_value_int64`, `sqlite3_value_double` or
     `sqlite3_value_text`, and 0, 0.0 or no text when none is left;
   - the doubles use `sqlite3FpDecode` (`RealText.lean`), with SQLite's NaN, infinity and
     sign-of-zero rules;
   - NULL without arguments or for a NULL format.
2. **Limits.** A width or a precision above 100000 is a value that the model does not
   describe (a `may` fault), so that a proof never builds a long text; SQLite allows up to its
   length limit.

## Tests

- Lean examples of each conversion and flag, with kernel proofs for a few.
- A differential check of the model against native SQLite over generated formats and values,
  run once and recorded in the status file (each conversion with each flag, width and precision
  form).
- An authored corpus (`conformance/authored_printf.py`), each case with a kernel proof,
  recorded as a new corpus: integer, double, text and quoting conversions, flags, `*`, missing
  arguments, the end of the output, and `printf` in writes.
- The verdict of every corpus: cases that newly agree and none that leave AGREE.
- Mutants: `%d` without the sign flag, `%g` that keeps trailing zeros, and `%q` that does not
  double quotes; each killed by an authored case.

## Key points

- **Files.** `Functions/Printf.lean` (the flag loop and the conversions),
  `Functions/PrintfNumbers.lean`, `Functions/PrintfText.lean`, `RealText.lean`
  (`decodeDouble`), `Functions/Scalar.lean`, `Resolution/ScalarFunction.lean`,
  `Resolution/FunctionCalls.lean`.
- **Byte positions.** The C code moves through the format with `++fmt` and `fmt--`; the port
  keeps the position of the conversion byte so that `%5.l` and `%*.*d` read as SQLite reads them.
