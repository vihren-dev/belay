## Owner decisions needed

1. **`withTransaction`.** The ADR's row of S3 does not name it; the guide uses a savepoint
   inside an open transaction, and the model has no `SAVEPOINT`. Recommended: defer it, with a
   row in ADR 0017's "Deferred, with their triggers" (trigger: `SAVEPOINT` in the model).
   Other options: only on an idle connection, with an error output when `BEGIN` fails; or a
   model slice for `SAVEPOINT` first.
2. **One `run` for scripts and programs** (guide open question 15). Recommended: a class from
   the argument to `Sql α`, with a default instance for `Sql α` (a scratch probe worked).
   Fallback: `db.run` for programs only, and a script is run as `db.run (send s)`.
3. **What a program gives when the run cannot go on, and for `Output.oneOf`.** Recommended:
   `Run.value : Option α`, `none` when the run ends with `Output.unmodeled` or fails the check
   of `Database.Valid`; `query` and `single` read the first result of `Output.oneOf`. Other
   options: `Except String α` with the reason; end the run at `Output.oneOf`.
4. **Which scripts `query` and `single` take.** Recommended: one statement of any form, so that
   `INSERT ... RETURNING` works. Other options: one read-only statement, as `Holds` takes; any
   script, with the output of its last statement.
5. **Parameters in `db!`.** Recommended: an error at the parameter. Other option: keep today's
   NULL.
6. **Argument names and the clock.** Recommended, in the task file: `?` and `?NNN` give
   `p` and SQLite's number; one argument for each name in the whole script; `#name` gives an
   argument as `:name` does; `$x` and `:x` in one script are an error; `Env.clock` is a clock
   for each statement index, and `clockAt` gives one time to every statement.
