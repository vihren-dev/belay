# S8: application interfaces and migration simulation

Status: [progress](20261024-surface-s8.status.md).
Specs: [ADR 0017](../docs/adr-0017-user-surface.md), S8 and the contextual-pairing

## Purpose and accepted meaning

Users can prove that every application built from paired interface calls has
the same observable behavior across a migration, including when earlier results
choose later calls and arguments. The proof lifts checked call contracts; it
does not sample a finite set of complete programs.

The owner accepted a correction to the original lifting premise: matching query
outputs alone is insufficient. Every paired call, including queries, must satisfy
the contextual commuting condition below. Queries advance the statement clock,
and a migration can observe that difference. Keep weaker query translation as
a useful separate claim, with proved sufficient bridges to the stronger premise.
Use the accepted explicit migration observation view, not ordinary full-trace
`≈` with a hidden exception. No SQL execution or failure is suppressed.

The owner also accepted an explicit interface-scoped relation beside full-state
simulation. Expansion and a write can produce identical rows but different
`total_changes()`: the native example gives 3 versus 4. The guide's positive
expansion theorem uses the scoped relation. Retain the full-state refutation.

## Required outcomes

- **Interfaces describe parameterized calls.** An interface has named or indexed
  entries with explicit argument types and script families. Entries can have
  different argument lists, and a script can contain more than one statement.
  The primitive accepts arbitrary Lean argument types/functions that construct
  supported scripts; common SQL parameter families have convenient syntax.
  Pairings identify an old and new entry with the same input domain. A missing
  partner or incompatible argument domain is diagnosed at the pairing.
- **Applications keep their call identity.** A constructive application
  representation or witness identifies each interface call and its arguments,
  pure results and result-dependent bind. Its interpretation is the existing
  `Sql` program. Expose the guide's membership concept and a checked translation
  to the new interface. Translation preserves the chosen control flow while
  replacing each identified call with its partner. It does not guess a call by
  comparing the printed SQL or by splitting an arbitrary flattened program.
  Duplicate/overlapping script families remain expressible with explicit entry
  identities. Ambiguous convenience inference gives a useful diagnostic.
- **The witness is usable computational data.** Users can run the original and
  translated programs and apply the lifting theorem to their common witness.
  Do not eliminate an arbitrary proof-only membership proposition into data,
  choose an unstated decomposition, or silently select a different pairing.
  A convenient proposition about an existing `Sql` program may be an image of
  the constructive representation, but executable translation has an explicit
  representation/witness route. The guide must show that route when inference
  cannot recover the intended interface calls.
- **Full-state simulation has full call conditions.** At an admissible shared
  clock, statement index and complete connection, running the old call and then
  the migration agrees with running the migration and then the paired new call.
  Both sides retain the call's returned outputs. The explicit observation view
  omits only the migration segment's compared outputs and retains its failures
  and termination information according to the S6 contract. Compare complete
  final context and every actual/raw/concrete branch outcome, including partial
  traces and stopped branches. Executed-step counts and later clock indices
  remain real; the view never resets them. Query pairs have this same obligation.
- **Scoped simulation names its context relation.** A separate primitive takes
  an explicit relation between an old-interface context and a new-interface
  context. A migration entry contract relates the original context to every
  admitted migrated context. Every paired call and
  argument must preserve it, agree on returned results and permitted observed
  traces, and match every raw/concrete/stopped branch in both directions.
  Establish actual-run agreement too; branch-set matching alone need not match
  the distinguished actual run. State the observation view and related clock,
  index, counters, settings and snapshots explicitly. These components still
  execute normally. A context component may differ only when the relation and
  every permitted call's observation/closure proof allow that difference.
  Counter/clock-sensitive calls satisfy the same obligations. No default rule
  hides counters, resets clocks or assumes that SQL reads cannot observe them.
- **Admissibility survives composition.** The public primitive accepts an
  arbitrary context invariant and the exact migration-success domain. State
  which starting contexts the relation covers and require preservation of that
  domain after every returning call outcome that can reach another call.
  The helper for a SQL `where` guard lifts its established observation meaning
  into this context predicate. Modeled errors, unmodeled termination and a
  failed migration are handled explicitly; none can silently discharge a
  successful simulation. No desired whole-program conclusion is itself a premise.
- **Both whole-program theorems are proved.** For every represented application,
  call arguments, initial admissible context and permitted result-dependent
  continuation, moving the migration from after the application to before its
  translated application preserves the accepted projected observation and full
  final context for full-state simulation. Scoped simulation compares the old
  application from an old context with the translated application from a
  related new context: equivalent permitted observations and related final
  contexts. Its migration corollary uses the entry contract. A comparison with
  migration applied after the old application additionally needs a proved
  relation between that migrated result and the new application's final result.
  Prove each by the actual call/bind contracts, with the same
  migration segment identified throughout. Keep ordinary `Sql.run` and strong
  `≈` unchanged. Provide interpretation/translation laws for pure, call and
  bind, and named theorems usable without the surface notation. Give sufficient
  bridges to the full-state theorem through the full per-call conditions;
  a scoped theorem alone never asserts equality of complete final contexts.
- **Weak query translation has honest bridges.** A query-output translation
  can contribute to simulation only with the additional proved context/frame
  conditions that establish its commuting square. Read-only syntax alone is
  insufficient. Expose a convenient sufficient rule for the admitted query
  family, while retaining the general semantic condition for callers outside
  that family. No duplicate effect framework is introduced; consume S6's laws.
- **The expansion example covers arbitrary applications.** An admitted schema
  gains a normalized copy of a field, a backfill and insert/update triggers that
  keep it current. Pair old computed lookups with new stored-column lookups and
  the corresponding parameterized writes. State an explicit scoped relation,
  prove its migration-entry and call obligations, and lift
  them to every represented application, including branches on prior results.
  State the schema, trigger/FK effect, counter, clock and invariant conditions
  actually needed. Preserve the native counter difference as a checked
  refutation of the full-state claim. Adding `total_changes()` to the interface
  must expose the failed scoped call condition for this relation. Preserve
  universal quantification over admitted databases;
  a single concrete database is only a test, not this theorem.
- **The missing-trigger bug remains visible.** Removing the synchronization
  trigger yields a kernel-confirmed failing application/witness: a later lookup
  observes stale normalized data after a write. The checker can display the
  witness and replay its SQL through the existing S5 path. Prove a reverse
  simulation separately when its hypotheses hold; a forward theorem does not
  imply rollback safety. Include a reverse-direction counterexample where data
  required by the older interface is lost.
- **The surface explains and checks the same proposition.** Interface,
  membership, translation and simulation conveniences elaborate to the public
  primitives. `where` and `#explain` report the actual domain, observation scope,
  context relation and call conditions. Distinguish the two simulation claims.
  Integrate simulation claims with existing checked search and automation;
  successful results require kernel proofs, and unsupported shapes remain
  unknown. Update private guide examples and formulas to the accepted view and
  contextual-pairing and scoped meanings. Do not copy private prose into the
  public repo.

## Tests and acceptance

Kernel fixtures establish pure/call/bind translation and the universal program
theorem. Exercise heterogeneous parameter lists, values chosen from prior rows,
multi-statement calls, duplicate script families with explicit identities,
ambiguous inference, mismatched partners and an attempted call outside the
interface. Check that interpreted original programs retain their exact behavior.

Cover raw oneOf continuations and all concrete alternatives, an alternative that
chooses a different next call, modeled errors followed by calls, stopped branches,
transaction snapshots, pragma/counter effects and changing clocks. A concrete
constant-row query and a migration that stores statement-clock time must refute
lifting from weak query translation alone. A restricted example must require
invariant/migration-domain preservation at intermediate calls.

The expansion fixture proves the scoped parameterized call conditions and
universal application result with kernel-checked axioms only. Check both
simulation theorems, the full-state bridge, failed counter/clock-call closure,
and a relation that initially holds but fails after an intermediate write.
A small concrete native
trace validates its SQL observations; the missing-trigger and reverse-direction
bugs have explicit checked witnesses. Recheck emitted replay/suggestion artifacts
with S5. Audit public theorems and examples for `sorryAx`, `ofReduceBool`, `_native`
and assumed execution/simulation soundness. Test installed-library usage and
actual elaborator diagnostics, not only internal constructors.

Two acceptance parts: public interface/application primitives and both lifting
theorems; query bridges, expansion/rollback examples and checker/guide integration.
Each coherent commit gets focused tests, dev-build and independent review.
Each part ends with post-review `just test-full` and `just verdict`; the task ends
with `just test-nix` and `just test-scheduled-checks` under the owner's override
in [the build-boundary status](20261024-text-build-boundaries.status.md).
Every subprocess test has a finite timeout. Only Nix results are implementation
acceptance evidence. Existing predictions and locked claims remain unchanged;
any required new corpus uses a separate judge PR with owner approval to merge.

## Prerequisites and ownership

view, context/frame laws and the named pattern contracts. S5 supplies certified
search/replay; S4 supplies run/success laws. The required expansion SQL consumes
the existing trigger/ALTER ADD COLUMN semantics and any separately specified
model correction established by its examples. No general attached databases,
concurrent execution, new SQL interpreter or unsound syntactic effect shortcut
belongs in this task.

At task creation these production S6/S8 modules do not exist. The predecessor
tasks and their final reviewed revisions must be integrated before implementation.
Keep typed calls, interpretation/translation, simulation laws and frontend
conveniences separate, with files below 200 lines and checked documentation.
