## Progress

- 2026-10-15: task and status files. Stacked on slice 5b (pull requests #134 and B).
  Native facts checked on SQLite 3.51.0: the target key is checked first, and a row that
  conflicts on it and on an untargeted key is handled by the clause; clauses are tried
  in written order; `NOT NULL` fails before conflict handling; a no-target clause before
  another clause is a syntax error; a non-unique index is no target; `excluded` has
  defaults and affinity; a `WHERE NULL` skips the row and is not counted.

- 2026-10-15: implementation (pull request A). Frontend: `belay/sqlite/syntax_conflicts.py`
  maps the clauses; `Syntax.Statement.insert` and `Syntax.Write.insert` have a
  `conflicts` list, so the expression syntax moved to `Resolution/SyntaxExpr.lean`.
  Resolution: `Resolution/Upserts.lean` (targets, the `excluded` scope, actions),
  `Resolution/Assignments.lean` (the SET lists of UPDATE and DO UPDATE), the prepare
  error `conflictTargetMismatch`, the restriction `conflict-without-target`, and the
  RETURNING path 4 of every write. Execution: `Resolved.Statement.upsert` and
  `Upsert.lean` (`upsertRow`, `upsertRun`, `upsertReady`); `RowUpdate.assignFrom`
  evaluates on a context. Proofs: `UpsertPreservation.lean`, `UpsertConforms.lean`
  (`literalStep_upsert_conforms`), `UpsertRules.lean` (no catalog object in clause
  errors). Outputs: RETURNING and the change count of written rows. Evidence:
  `UpsertExamples.lean`, 32 authored cases (`conformance/authored_upserts.py`, all
  AGREE), 7 mutants (`conformance/upsert_mutants.py`), the corpus 19 writer. The mutant
  classifier gives each case its own Lean definition, because the heartbeat limit of
  one list definition was reached. The frozen fixtures `charint_key`,
  `integer_key_desc` and the injected regression case gain `"conflicts": []`. `test-full`
  passes.
